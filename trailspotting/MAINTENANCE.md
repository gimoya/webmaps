# Trailspotting Maintenance Guide

This guide explains how to add new GPX routes and manage the Trailspotting web application.

## Track Naming System

GPX files use a descriptive naming scheme based on segment locations (e.g., `Hu_NR__Trailspotting.gpx` for Hungerburg → Neu-Rum). This allows stable A-Z route IDs while using meaningful filenames.

**Naming Convention:**
- Filenames are generated from segment locations (e.g., "Aldrans" → "Al", "Hall" → "Ha")
- Multiple segments are joined with underscores (e.g., `Al_Ha_Mue_Br_Sc_Te__Trailspotting.gpx`)
- Umlauts are replaced: Ö→Oe, Ü→Ue
- Case is preserved from location names

**Internal Mapping:**
Route IDs (A-Z) are keyed in `ROUTE_CONFIG` with the filename included in each route's configuration. This ensures:
- Stable route IDs regardless of file changes
- Descriptive filenames based on segments
- Easy maintenance when routes are added/removed
- All route information (filename, segments, stations) in one place

## Adding a New GPX Route

### Step 1: Add GPX File
1. Place your new GPX file in the `tracks/` directory
2. Name it based on segment locations (see naming convention above)
   - Example: For segments "Aldrans → Hall, Schwaz → Terfens", name it `Al_Ha_Sc_Te__Trailspotting.gpx`
3. Ensure the GPX file has valid XML structure with `<trk>`, `<trkseg>`, and `<trkpt>` elements

### Step 2: Calculate Statistics
Run the Python script to calculate route statistics:
```bash
python clean_and_calcstats_gpx.py
```
This will update the GPX file with distance, elevation, and estimated duration. The script also:
- Removes unnecessary XML extensions and tags
- Strips namespace prefixes for compatibility
- Keeps only essential GPX elements (trkpt, lat, lon, ele, name, desc, trkseg, trk)
- Formats statistics: distance (1 decimal), elevation (whole numbers), speeds (1 decimal)

**Statistics Formatting:**
- Distance: 1 decimal place (e.g., "5.0 km")
- Elevation gain/loss: Whole numbers (e.g., "123 m")
- Average speeds: 1 decimal place (e.g., "15.5")
- Durations: HH:MM format

### Step 3: Update Configuration
In `config.js`, make these updates:

**A) Add route to activeRoutes:**
```javascript
const APP_CONFIG = {
    activeRoutes: ['A', 'B', 'C', 'D', 'E', 'F', 'G', 'H', 'I', 'J', 'K', 'L', 'M', 'N'],  // Add 'N'
    
    routeOverrides: {
        'B': { minZoom: 9 }  // Example: Route B has different minZoom
    }
};
```

**B) Add route configuration with filename, segments and stations:**
```javascript
const ROUTE_CONFIG = {
    'N': {
        filename: 'Al_Ha_Sc_Te__Trailspotting.gpx',  // GPX filename
        segments: [
            {from: 'StartLocation', to: 'EndLocation'},
            {from: 'AnotherStart', to: 'AnotherEnd'}
        ],
        stations: [
            'Station Name 1',
            'Station Name 2',
            'Station Name 3'
        ]
    }
};
```

**⚠️ CRITICAL: Station names in `ROUTE_CONFIG.stations` must EXACTLY match keys in `STATIONS_CONFIG`**

**C) Add stations to STATIONS_CONFIG (if new stations are needed):**
```javascript
const STATIONS_CONFIG = {
    'Station Name 1': {
        iframeUrl: 'https://timeview.vvt.at/#YOUR-STATION-ID'
    },
    'Station Name 2': {
        iframeUrl: 'https://timeview.vvt.at/#ANOTHER-STATION-ID'
    },
    // ... existing stations
};
```

**Note:** If a station doesn't have a timetable URL, use an empty string:
```javascript
'Station Name Without Timetable': {
    iframeUrl: ''
}
```

### Step 4: No HTML Changes Needed
Timetable boxes are now dynamically generated by JavaScript. The application will automatically:
- Create timetable boxes for all stations in `STATIONS_CONFIG`
- Show/hide boxes based on the selected route's stations
- Handle lazy loading of iframes
- Display error messages for configuration issues or iframe load failures

**That's it!** The application will automatically:
- Load cycling segments for the new route
- Create the map with proper styling
- Add GPX download link to the scrolling list
- Generate and manage timetable boxes
- Handle all the JavaScript processing

## Modifying Existing Routes

### If GPX Content Changed
1. Replace the GPX file in `tracks/` directory (keep the same filename)
2. Run: `python clean_and_calcstats_gpx.py`
3. No other changes needed

### If Station Names Changed
1. Update the `ROUTE_CONFIG[routeLetter].stations` array in `config.js`
2. Update the corresponding keys in `STATIONS_CONFIG` (or add new entries)
3. Ensure names match exactly between both configs

### If Segment Names Changed
1. Update the `ROUTE_CONFIG[routeLetter].segments` array in `config.js`
2. If the filename should change, rename the GPX file and update `ROUTE_CONFIG[routeLetter].filename`
3. No other changes needed

## Removing Routes or Displaying a Subset

### Removing a Route from Display

To hide a route from the application (without deleting files or config):

1. **Remove from activeRoutes array** in `config.js`:
```javascript
const APP_CONFIG = {
    activeRoutes: ['A', 'B', 'C', 'D', 'E', 'F', 'G', 'H', 'I', 'J', 'K', 'L'],  // Removed 'M'
    
    routeOverrides: {
        'B': { minZoom: 9 }
    }
};
```

**That's it!** The route will:
- Not appear in the route selector
- Not be available for selection
- Not appear in the GPX download list
- Still exist in `ROUTE_CONFIG` (can be re-enabled later)

### Displaying Only a Subset of Routes

To show only specific routes (e.g., for testing or seasonal routes):

1. **Update activeRoutes array** to include only desired routes:
```javascript
const APP_CONFIG = {
    activeRoutes: ['A', 'B', 'C'],  // Only show routes A, B, and C
    
    routeOverrides: {
        'B': { minZoom: 9 }
    }
};
```

**Example use cases:**
- **Seasonal routes**: Show only summer routes, hide winter routes
- **Testing**: Show only new routes being tested
- **Event-specific**: Show only routes for a specific event
- **Difficulty levels**: Show only beginner routes

### Completely Removing a Route

To permanently remove a route (including its configuration):

1. **Remove from activeRoutes** (see above)
2. **Optionally remove from ROUTE_CONFIG**:
```javascript
const ROUTE_CONFIG = {
    'A': { ... },
    'B': { ... },
    // 'M': { ... },  // Removed
};
```

3. **Optionally delete the GPX file** from `tracks/` directory (if no longer needed)

**Note:** It's recommended to keep routes in `ROUTE_CONFIG` even if removed from `activeRoutes`, so they can be easily re-enabled later without reconfiguration.

## Configuration File Structure

All configuration is centralized in `config.js`:

### STATIONS_CONFIG
Centralized configuration for all timetable stations:
```javascript
const STATIONS_CONFIG = {
    'Station Name': {
        iframeUrl: 'https://timeview.vvt.at/#STATION-ID'
    },
    'Station Without URL': {
        iframeUrl: ''  // Empty string if no timetable available
    }
};
```

**Error Handling:**
- If a station in `ROUTE_CONFIG.stations` doesn't exist in `STATIONS_CONFIG`: Shows "⚠️ Config file set up error"
- If `iframeUrl` is empty or missing: Shows "⚠️ Config file set up error"
- If iframe fails to load: Shows "🚫 Service not avail. at the moment"

### APP_CONFIG
```javascript
const APP_CONFIG = {
    activeRoutes: ['A', 'B', 'C', 'D', 'E', 'F', 'G', 'H', 'I', 'J', 'K', 'L', 'M'],
    
    routeOverrides: {
        'B': { minZoom: 9 }  // Route-specific settings
    }
};
```

### ROUTE_CONFIG
Each route has `filename`, `segments`, and `stations`:
```javascript
const ROUTE_CONFIG = {
    'A': {
        filename: 'Hu_NR__Trailspotting.gpx',  // GPX filename
        segments: [
            {from: 'Hungerburg', to: 'Neu-Rum'}
        ],
        stations: [
            'Innsbruck Marktplatz',
            'Rum BHF'
        ]
    }
};
```

**Important:** 
- Station names in `stations` array must exactly match keys in `STATIONS_CONFIG`
- The `filename` property specifies the GPX file in the `tracks/` directory
- This structure keeps all route information (filename, segments, stations) in one place

```javascript
const MAP_CONFIG = {
```


**Note:** The `filePattern` is legacy. Actual filenames are specified in `ROUTE_CONFIG[route].filename`.

## Key Features

- **Dynamic Route Loading**: Routes are loaded automatically based on `APP_CONFIG.activeRoutes`
- **Unified Route Configuration**: All route information (filename, segments, stations) stored in `ROUTE_CONFIG` keyed by route letters
- **Automatic GPX Downloads**: Download links are generated automatically
- **Centralized Configuration**: All settings in `config.js`
- **Dynamic Timetable Generation**: Timetable boxes are created from `STATIONS_CONFIG` and shown/hidden based on route selection
- **Lazy Loading**: Iframes load only when their timetable box becomes visible
- **Error Handling**: Clear error messages for configuration issues and iframe load failures
- **Route-Specific Overrides**: Custom settings for individual routes
- **Statistics Calculation**: Python script processes GPX files and calculates timing with proper rounding
- **MapTiler Integration**: Uses MapTiler outdoor-v4 tiles for map display
- **Marker Styling**: Configurable marker sizes and colors via CSS custom properties
- **Formatted Display**: Statistics display with spaces between numbers and units (e.g., "5.0 km", "123 m")

## Troubleshooting

### Route shows "no segments found"
1. Check GPX file exists in `tracks/` directory with correct filename (check `ROUTE_CONFIG[route].filename`)
2. Verify GPX file has valid XML structure (check for syntax errors)
3. Ensure GPX file contains `<trk>` and `<trkseg>` elements
4. Run `python clean_and_calcstats_gpx.py` to process the file
5. Verify the filename in `ROUTE_CONFIG[route].filename` matches the actual file

### Timetable box shows "Config file set up error"
1. Verify station name in `ROUTE_CONFIG[route].stations` exactly matches a key in `STATIONS_CONFIG`
2. Check that `STATIONS_CONFIG[stationName].iframeUrl` is not empty (unless intentionally left blank)
3. Station names are case-sensitive and must match exactly including spaces and special characters

### Timetable box shows "Service not avail. at the moment"
- The iframe failed to load from the remote server
- This is a network/server issue, not a configuration problem
- The iframe will retry automatically when the route is selected again

### Map not displaying
1. Check `MAP_CONFIG.maptilerKey` is valid
2. Verify `MAP_CONFIG.mapSource` URL format is correct
3. Check browser console for network errors

### Track file not found
1. Verify the filename in `ROUTE_CONFIG[route].filename` matches the actual file in `tracks/` directory
2. Check for typos in the filename property (case-sensitive)
3. Ensure the file exists and has `.gpx` extension
